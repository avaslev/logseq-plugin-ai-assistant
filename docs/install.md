# Установка

[← К README](../README.md)

## Требования

- Logseq для десктопа — плагины работают в приложении, а не в веб-версии
- Сервер с OpenAI-совместимым API: LM Studio, Ollama, OpenRouter, OpenAI или любой другой
- Node.js и npm — только если собираете плагин из исходников

## Через маркетплейс

1. Откройте Logseq → `Plugins` → `Marketplace`
2. Найдите плагин `logseq-ai-graph-assistant`
3. Установите его и откройте настройки: `Settings` → `Plugin Settings` → `AI Assistant`

## Вручную из исходников

```bash
npm install
npm run build
```

В Logseq включите режим разработчика (`Settings` → `Advanced` → `Developer mode`), затем `Plugins` → `Load unpacked plugin` и выберите корневую папку проекта — ту, где лежит `package.json`.

После каждой правки кода пересоберите плагин (`npm run build`) и перезагрузите его в Logseq. Без пересборки Logseq продолжит работать со старой сборкой из `dist/`.

## Первый запуск

1. `Settings` → `Plugin Settings` → `AI Assistant`
2. Заполните **API base URL**, например `http://localhost:1234/v1` для LM Studio
3. Перезагрузите плагин — после этого подгрузится список моделей
4. Выберите **Default model**
5. Откройте правую панель Logseq: внизу появится поле ввода ассистента

Иконка робота на панели инструментов Logseq открывает страницу `ai_assistant` со списком всех сессий.

## Обновление

- Из маркетплейса — через `Plugins` → `Marketplace`
- Из исходников — `git pull && npm install && npm run build`, затем перезагрузка плагина

## Типовые проблемы

| Проблема | Что сделать |
|---|---|
| Пустой список моделей | Проверьте **API base URL** и доступность сервера, затем перезагрузите плагин |
| Ошибка сети или CORS | Разрешите источник плагина в настройках вашего локального сервера или используйте сервер без ограничений |
| Поле ввода не появляется | Откройте правую панель Logseq (`Right sidebar`); форма показывается только при открытой панели |
| Изменения в коде не видны | Пересоберите `dist` и перезагрузите плагин |
