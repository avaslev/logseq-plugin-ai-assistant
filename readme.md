# Logseq AI Assistant

Плагин для [Logseq](https://logseq.com), добавляющий чат с AI-ассистентом, интегрированным в граф знаний. Переписка хранится в графе: каждая сессия — отдельная страница в неймспейсе `ai_assistant/`.

## Возможности

- 🤖 Иконка в тулбаре плагинов — открывает страницу `ai_assistant` со списком всех сессий
- 💬 Поле ввода внизу правой панели Logseq (появляется автоматически, когда панель открыта)
- Многострочный ввод: Enter — отправка, Shift+Enter — новая строка, авторост поля
- **Стриминг ответа**: текст печатается в блок сессии в реальном времени
- **Инструменты агента**: поиск по графу, чтение страниц и блоков, контекст текущей страницы; ссылки на найденные блоки через `((uuid))`
- **MCP**: подключение внешних инструментов по HTTP (Streamable HTTP / SSE)
- Сессии создаются лениво: при первой отправке, если активной страницы ассистента в панели нет
- Имя страницы сессии: `ai_assistant/20261104_143205_начало-сообщения` (санитизация спецсимволов)
- Первый блок сессии — метаданные: `model::`, `started::`
- Выбор модели на сессию в футере формы; новая сессия стартует с модели из мета-блока (или дефолтной)
- История сессии передаётся модели как контекст (последние ~30 блоков)
- Адаптация под тему Logseq через CSS-переменные `--ls-*`

## Настройки

Настройки плагина (Settings → Plugin Settings → AI Assistant):

| Параметр | Описание |
|---|---|
| **API base URL** | OpenAI-совместимый эндпоинт: `http://localhost:1234/v1` (LM Studio), `http://localhost:11434/v1` (Ollama) и т.п. |
| **API token** | Bearer-токен; для локальных серверов обычно пустой |
| **Default model** | Список подгружается с сервера автоматически после заполнения URL |
| **MCP servers (JSON)** | Массив серверов: `[{"name":"my-mcp","url":"http://localhost:8000/mcp","headers":{"Authorization":"Bearer x"}}]` |

Логика моделей: дефолтная модель из настроек используется для новых сессий; в футере формы можно выбрать другую модель — выбор действует только на текущую сессию и записывается в её мета-блок. При повторном открытии сессии подхватывается модель из мета-блока (если она недоступна на сервере — дефолтная).

## Инструменты агента

Агент умеет читать граф (только чтение):

- `search_graph` — поиск подстроки по именам страниц и содержимому блоков
- `get_page`, `get_page_blocks` — метаданные и содержимое страниц
- `get_block` — блок с дочерними блоками
- `get_current_page` — страница, открытая у пользователя в основном редакторе

Ответ агент формирует с учётом синтаксиса Logseq: перенос строки = новый блок, списки — отдельными блоками, вложенность — дочерними блоками. Найденные блоки агент цитирует ссылками `((uuid))` — только когда это уместно.

## MCP-серверы

Поддерживаются серверы с транспортом HTTP (Streamable HTTP / SSE). Локальные stdio-серверы из песочницы плагина недоступны напрямую — используйте мост:

```bash
npx supergateway --stdio "npx -y @modelcontextprotocol/server-filesystem /path/to/dir" --port 8000
```

и укажите в настройках `{"name":"fs","url":"http://localhost:8000/mcp"}`.

## Разработка

Требуется Node.js и npm.

```bash
npm install
npm run dev     # дев-режим с HMR
npm run build   # прод-сборка (tsc && vite build)
npm test        # юнит-тесты (vitest)
```

Подключение к Logseq: включите режим разработчика → Плагины → «Load unpacked plugin» → выберите корневую папку проекта (с `package.json`).

## Структура

- `src/main.tsx` — регистрация плагина, иконка в тулбаре
- `src/App.tsx` — форма ввода, отслеживание правой панели, селектор модели
- `src/chat.ts` — сессии и страницы графа, конвейер отправки сообщения
- `src/settings.ts` — настройки плагина и загрузка списка моделей
- `src/llm.ts` — клиент OpenAI-совместимого API (SSE-стриминг, tool-loop)
- `src/logseqTools.ts` — инструменты агента для работы с графом
- `src/mcp.ts` — MCP-клиент (HTTP)
- `src/format.ts` — форматирование ответов под блоки Logseq
- `tests/` — юнит- и интеграционные тесты (мок-серверы OpenAI/MCP)

## Стек

TypeScript, React 18, Vite, TailwindCSS, [@logseq/libs](https://github.com/logseq/logseq), vitest, npm.
